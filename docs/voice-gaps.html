The eight gaps

Done

Interrupting the assistant

You can interrupt the assistant while it speaks. The assistant then stops. Before the fix, the assistant assumed that you heard the complete reply. Its next answer repeated sentences that you did not hear.

Now the assistant stores the part of the reply that played before the interruption. Its next answer continues from that part.

Item 1 (barge history trim)

Done

Timing of the assistant's decisions

The assistant decides when to let you speak and when to react with a short sound. These decisions use audio timing. The old code used the time when audio entered the play queue. That time can be earlier than the time when you hear the audio. The difference can reach a few seconds.

The code now uses the real playback time. The decisions now match what you hear.

Conversation settings

Three settings control the assistant. One setting decides when you finished speaking. One setting decides when you interrupted the assistant. One setting decides when the assistant reacts with a short sound such as "mm-hm". We used generic values. These values missed interruptions and produced too few reactions.

We now use the values that the reference system uses in live calls.

Item 3 (thresholds)

Needs your decision

Speaking the answer in parts

The assistant writes its complete answer first. Then it speaks the answer. When the answer takes time, you hear nothing during that time. The fix is to speak each sentence when the sentence is ready.

We completed and tested the speech part. The missing part is the code that sends each sentence to the speaker during a call. There are two ways to do this.

Choice A: send the sentences on the call connection

The sentences travel like the voice audio. They do not enter the chat history. Delivery is fast. App versions that predate this change are not affected.

The call connection cannot carry these sentences today. We would add that capability.

Choice B: send the sentences as chat messages

Each sentence arrives as a chat message with a "partial" marker. The final message replaces the partial messages with the complete answer. No new capability is necessary.

The chat history then contains many partial messages. App versions that predate this change would speak each partial message as a complete answer.

My recommendation is A. Tell me your choice and I will build it.

Item 4 (reply deltas)

Done today

What the assistant says during long waits

The assistant can take time to answer, for example when it looks up information. It now speaks short lines during these waits. After two seconds of silence it speaks one line, such as "Let me check on that." If the wait continues, it can speak up to two more lines.

A small language model in the app writes these lines. The main model does not write them. These lines do not enter the conversation history.
