# idfon Native SDK addendum

Provenance: the `native-sdk` skill is vendored from `vercel-labs/native` and managed by the `skills` CLI, which owns `idfon/.agents/skills/native-sdk/` and rewrites it on every update. Never edit that copy — keep idfon-specific lessons here. Load `native-sdk` (`native skills get core`, plus `native-ui` and `ts-core`) for the SDK itself.

## Hard-won rules (idfon project experience)

Learned from real checker/compile failures on this repo's ~1000-line Elm-style `native/src/core.ts`. The `native skills get ts-core` docs are authoritative; these are the rules that actually bit:

- **`native check` is lenient; `native test` is strict.** `check` runs the subset checker over `core.ts`/markup/manifest; `test` and `build` run the full `scriptc` compiler. Code can pass `check` and fail `test`. Run both before committing.
- **NS1017 — Cmd lives only in `update`.** `Cmd.request`/`Cmd.batch` may only be constructed in the exported `update` function's return path. Extracting the update switch into a helper (`transition(model, msg)`) or wrapping `update` makes the checker treat every inline Cmd as "stored" and rejects the file. Keep the switch inside `update` itself; helpers must stay Cmd-free and Cmd-carrying types may only flow through `update`'s own returns.
- **SC1090 — no object spread of computed sources.** `{ ...someFn(model, patch), extra: x }` is rejected ("the field copies re-read the source — bind it to a const first"), and the same applies when the call's argument is itself a computed spread. Fix: `const next = someFn(model, patch); return { ...next, extra: x };` or restructure so the helper receives a plain identifier and returns the final object.
- **Determinism: no ambient time in `update`.** The checker forbids `Date.now()`/env reads inside `update` (updates must replay deterministically). Time arrives as data: a `Sub.timer` subscription emits a Msg carrying the timestamp (e.g. a `tickAt` field), and anything derived from time (idempotency keys, expirations) must be built from that field.
- **Keyed effects are an in-flight guard.** `Cmd.request(..., { key })` — a second request with the same key while one is in flight is rejected at the engine. Use one stable key per operation kind; don't share a key across different request types.
- **`viewUnbound` declares intentional gaps.** Model fields that exist for logic but not markup, and message tags with no view binding, must be listed in the exported `viewUnbound` array or the checker warns about unbound model fields/message tags.
- **The model contract goes stale.** After editing `core.ts`, `native check` may report `zig-out/model-contract.zon is stale ... bindings checked structurally only`. Refresh with `native test` (or `zig build model-contract`) before trusting a clean check.
- **SC4013 — never spread a `Partial<T>` parameter into a record.** `{ ...model.comms, ...patch }` compiles clean but at runtime the scriptc runtime materializes the Partial with `undefined` for absent fields, so absent fields stamp `undefined` onto the target and any later assignment into a required field traps: `panic: Uncaught TypeError: undefined is not representable in the target union (SC4013)` in `nsc_core_dispatch_bytes`, aborting the app. The panic text blames "contract skew" — misleading; a full rebuild does NOT fix it. Fix: merge each field explicitly (`audio: patch.audio ?? model.comms.audio, ...`). Cost a full day of crash-hunting; bisect by neutralizing one case body to locate the failing helper.
- **Elm-style derive pattern that works:** keep canonical state in one struct field on the Model (e.g. a `Comms` struct), derive display flags in a pure `settle()` function, route every update arm through a Cmd-free `comUpdate(model, patch)` helper that returns a settled model. This prevents the desync class where parallel flat flags drift apart across error paths.
- **Editing discipline for large core files:** grep the exact verbatim line immediately before each edit; one edit per tool call; `native check` after every change; commit at each green checkpoint. Failed edit batches are atomic — verify with `git status`/`git diff` rather than assuming partial application, and revert to the last committed green state rather than patching forward from a corrupted file.
- **All-digits attribute values kill the runtime view builder.** `placeholder="32"` passed `native check`, `markup check --strict`, and `markup dump` — then the app showed a blank window: the runtime's dynamic attribute tokenizer rejects a bare number token (`markup view failed to build (21:5): expected text`) and drops the ENTIRE view, not just the element. Fix: any non-numeric text (`placeholder="e.g. 32"`). The static checker never sees this class of bug — `native check`/`markup dump` parse with a different (lenient) parser than the runtime view builder.
- **Blank window = runtime view-build failure; find it in the log.** The app runs and GPU frames flow, but no markup error reaches `native check`. Run the binary directly (stderr lands in the log even via `open`: log to a file first) and grep `markup view failed to build (line:col): ...` — the position names the offending element. Bisect by cloning the nearest working element verbatim, then change one attribute per rebuild; the clone trick isolates position vs. attribute value vs. binding in 3–4 builds. `native markup dump` shows the parsed tree with each attr typed (literal/binding/message) — closest thing to a schema inspector; full tag/attr reference in `native skills get native-ui`.
- **Streaming-chat reference:** `examples/chatbot` in the SDK repo is the reference TS-core pattern for streaming AI chat (SSE line routing through `Cmd.fetch`, composer as `input-group` + `textarea` with icon action buttons, sending/failed rows, record/replay).
